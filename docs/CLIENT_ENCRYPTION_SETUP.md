# 暗号化ファイルの初回設定

対象は、暗号化版を配備した後の private ブラウザー画面です。Cloudflare Access のログインと、ファイルの復号鍵の解除は別の操作です。

## 1. 管理者が先に設定する

1. 管理者でログインし、ナビゲーションの「暗号化ファイル」を開きます。staging は [暗号化設定](https://staging-app.darask.date/encryption) です。
2. 「暗号化鍵を作成」→「復旧ファイルを保存」を選びます。
3. 「保存したファイルを選択」で、いま保存した復旧 JSON を読み込みます。復旧できることを確認すると鍵が使えるようになります。
4. 「公開鍵を保存」で、管理者の公開鍵 JSON を別に保存します。
5. 一般利用者へ渡すのは **公開鍵 JSON だけ** です。復旧 JSON は渡しません。利用者が表示した管理者アカウント ID と鍵の指紋を、別の信頼できる経路で公開鍵 JSON の内容と照合します。

復旧 JSON には復号に必要な秘密が含まれ、ファイル自体にパスワード保護はありません。このサービス、チャット、Git、共有フォルダーへアップロードせず、暗号化した端末領域や安全なオフライン媒体に保管してください。管理者の復旧 JSON は、管理者向けに暗号化された全利用者のファイルを開ける重要な鍵です。

## 2. 一般利用者がそれぞれ設定する

1. 本人のアカウントで「暗号化ファイル」を開き、自分用に鍵を作成します。
2. 自分の復旧 JSON を保存し、同じファイルを読み込んで復旧を確認します。
3. 「管理者公開鍵ファイルを確認」で、管理者から受け取った **公開鍵 JSON** を選びます。
4. 表示された管理者アカウント ID と指紋を照合し、「この公開鍵を固定」を選びます。
5. 「暗号化してアップロード」で保存します。新しいファイルは、本人と固定した管理者の両方が自分の鍵で復号できます。

各利用者は別々の鍵を使います。管理者の復旧 JSON を各利用者に配って設定する方法は使いません。

## 3. 閲覧・ダウンロード・再ログイン

- 「復号して開く」で、元のファイル名と画像・音声・動画を端末内で復号します。「復号して保存」で元のファイルをダウンロードできます。
- 管理者は「暗号化ファイルの所有者」で利用者を選択します。管理者の閲覧・ダウンロードは監査履歴に記録されます。
- 再読み込みや別のブラウザーでは、自分の復旧 JSON を読み込んで鍵を解除します。Access の PIN だけでは復号できません。
- 本人の復旧鍵だけで既存ファイルを読めます。別のブラウザーから新たにアップロードするときは、管理者の公開鍵も再び照合・固定してください。
- 「このタブでロック」は、そのタブの鍵と復号プレビューを破棄します。他のタブも解除していれば、それぞれでロックしてください。
- 管理者の鍵を後から変更しても、古いファイルへ自動的に新しい鍵は追加されません。元の鍵を保管してください。

## 4. 既存ファイルを移す

128 MiB 以下の既存ファイルは、同じ画面の「暗号化コピーを作成」で移せます。それより大きなファイルは、端末へダウンロードしてから暗号化アップロードします。

まず新しいコピーを復号・ダウンロードして内容を確認します。元の平文ファイルと過去の平文バックアップは自動削除されません。この確認だけで「古いデータもCloudflareから読めなくなった」とは言えません。

## 対応範囲

暗号化対象は、このブラウザー経路で新たに保存したファイル本体と元のファイル名です。フォルダー名、階層、サイズ、アクセス記録はサーバーに残ります。WebDAV、公開アップロード、直接 API からの保存は暗号化に未対応です。暗号化ファイルの公開共有・上書きは現在の UI では無効です。

この仕組みは、保存先で暗号文だけを読まれても内容を復号できないようにします。Cloudflare によるサービス停止・削除や、配信する JavaScript の改変まで防ぐものではありません。技術的な範囲と残る試験は [CLIENT_ENCRYPTION](CLIENT_ENCRYPTION.md) を参照してください。
