## 修正した問題

### 中: EPUB の索引取得が予算予約より先に実行される

`streamBudgetedEpubSelection` はページの予算を予約する前に索引を R2 から取得していた。
存在しないページの指定や予算不足の場合も索引を取得できるため、既存の request 上限が索引読み出しを制限していなかった。

索引を取得する前に `indexBytes` を予約し、取得開始後の失敗や不明な結果も保守的に計上する。
正常に索引を取得した後は、その費用を精算してから本文用の予約を行う。本文予約は 0 byte の場合も行い、現行権限と並列数を再検査する。
配信期限は最初の索引予約を超えない。

この修正は `max(索引bytes, 応答bytes, 圧縮entrybytes)` という概算を使う。索引と本文の費用を単純加算する方式ではない。
正常なページ要求は request 枠を 2 件、無効な entry は 1 件消費する。
認可確認で読む target manifest はこの索引予約より前にあり、すべての R2 読み出しがゼロになる保証ではない。

### 中: 完全削除が未確定アップロードの予約と追跡を削除する

同期・非同期の完全削除は、親または上書き先が削除対象である upload の容量予約を無条件に解放し、upload 行を削除していた。
外部書き込みがまだ完了していない場合、処理結果が確定する前に予約と cleanup の追跡が失われる。

完全削除の公開 transaction 内で、該当 upload が安全に削除できる状態かを共通の条件で検査する。
未確定の書き込みがある間は完全削除を拒否して予約を保持する。
未開始・正常完了済み、または既存 cleanup により不在確認／物理容量計上と GC への引き継ぎが確定した状態は許可する。
DB の migration や、既存 cleanup の終了証明を弱める変更は行わない。

## 確認済みの認証・暗号化条件

- NCFENC2 は登録済み所有者の署名鍵、所有者 ID、受信者ラップ、暗号化メタデータ、サイズ、ヘッダーハッシュを照合する。
- 暗号化 upload の完了時は実際の R2 ヘッダーと ETag を確認し、公開 transaction でも現在の所有者・管理者の鍵を確認する。
- 鍵の登録 challenge は account、credential、epoch、有効期限へ固定し、RSA と Ed25519 の秘密鍵の所持を確認する。
- 管理者の本文配信は監査記録の書き込み完了を待つ。監査記録の失敗、対象 node の差し替え、セッション失効、管理者降格を拒否する。
- ticket/session は現在の認証情報と配信対象へ結び付け、署名・期限・失効・共有範囲を検査する。

対応する拒否系テストは `signedContainer.test.ts`、`encryption-keys.test.ts`、`encryption-attestations.test.ts`、`single-upload.test.ts`、`content-tokens.test.ts`、`content-session.test.ts`、`admin-browse.test.ts` にある。

## 棄却した候補

非同期 restore/purge の `sourceGuard` が trash actor 一致を要求することを調査した。
共有コンテキストのない非所有者の user は trash を実行できず、共有 DAV の削除は 1,000 件までに制限される。
非所有者が 1,001 件以上の trash manifest を作る公開入口を確認できないため、候補の非同期経路には到達せず、修正対象としなかった。

## 残る削除の制約（静的確認）

ID が不明になった multipart upload の inventory/closure 処理は、変更不可の `multipart_inventory_scans` と `multipart_upload_settlements` を残す。
これらの `uploads` への外部キーにより、該当 upload を含む親フォルダー等の完全削除は、今回の変更前から拒否される。
通常の既知 ID に対する cleanup 後の完全削除とは異なる経路である。

正規の生成経路と DB 制約はソースで確認したが、この特殊な closure 経路の実行再現は今回行っていない。
今回の修正は未確定な予約の早期解放を防ぐものであり、この履歴を含む完全削除を可能にするものではない。
終了証明を維持したまま履歴と削除対象の参照を分離する設計は、別途必要となる。

## 保証の範囲

これは限定したソースレビューと試験の結果であり、脆弱性が存在しないことの証明ではない。
配信 JavaScript を変更できる提供者から鍵を守る保証、紛失した復号鍵の再生成、すでに取得された鍵・平文の回収は含まない。
フォルダー階層・サイズ等のメタデータはサーバーに残る。

管理者 receipt は鍵アクセスとメタデータ・先頭チャンクの確認であり、全ファイルの復元試験の代わりではない。
KDF の完了証明が全て失われた場合の安全側への停止、複数送信元による共有 session 枠の消費、大容量・長時間・暗号化 multipart 再開などの未検証範囲は既存文書のとおり。

今回のレビューは Cloudflare staging の配備やローカル週次バックアップ runtime の切り替えを含まない。
