### 確定方針（ラウンド3）

1. **JWT 受入プロファイル (A1〜A3)**: 入力は `Cf-Access-Jwt-Assertion` ヘッダのみ（`CF_Authorization` Cookie は private API では読まない。SPA からの fetch は同一オリジンで Access がヘッダを付与するため不要 — Access がヘッダを付けない経路（CONTENT_HOST 等）は private API を置かない）。alg = RS256 のみ許可、`iss = https://<team>.cloudflareaccess.com`、`aud` は route ごとに固定（private app AUD）、`exp/nbf/iat` を clock skew 60 秒で検証、`sub` 非空 + `email` を user token の必須 claim、service token は `common_name` claim で識別し **user とは別 principal 型**（`sub` 空文字を user として扱わない）。JWKS は KV に 1 時間キャッシュ + 未知 kid で 1 回だけ再取得（再取得は 1 分あたり 10 回に制限、超過は 503）。取得失敗時は既存キャッシュがあれば使用（最長 24 時間）、無ければ fail closed。
2. **失効連携 (A4)**: 伝播遅延の上限を明記: Access セッション失効 → 最長 JWT 残存時間（Access セッション長を 24h 以下に設定推奨、アプリは `iat` から 24h 超の token を拒否）。アプリ側 `users.disabled_at` は全 private request で D1 primary から確認（KV キャッシュしない、1 クエリ、`users` は小さい）。app password / share / job は各リクエスト時に D1 で状態確認（キャッシュ無し）。`POST /api/v1/auth/logout` は Access の `/cdn-cgi/access/logout` へリダイレクトし、直前に自分の unlock Cookie と SPA キャッシュを消す。
3. **endpoint manifest (Z1, Z3)**: `routes.ts` を **宣言的 manifest**（`{ method, path, auth: 'access'|'app_password'|'share'|'public'|'service', operation, operands: [param → 種別], adminOnly }`）として定義し、Hono の登録は manifest から生成。CI テストで「全 route が manifest に存在」「manifest の operation ごとに authorize が呼ばれる」ことを検証（handler は `authorize` の戻り値型 `Authorized<...>` を要求）。ID 所有者例外: upload/job/idempotency の終端結果再生は「同 principal かつ同 credential_id」のみ。owner / admin / 一般 member / 制限付き credential（app password scope, share）を明確に分離した権限表に更新。
4. **祖先有効性 (Z2)**: 全 read（content/thumb/children/search/zip/gallery/tracks/library）でも `authorize` 内で space root までの祖先が `deleted_at IS NULL` かつ同 space であることを再帰 CTE で検査（深さ ≤ 64、1 クエリ）。共有 root の祖先が trash に入った時点で共有は即失効（`shares.disabled_reason='trashed'` 設定は非同期でもよいが、判定は祖先検査で同期的）。
5. **復旧 epoch と進行中 request (Z4)**: fsMutation の D1 batch に `WHERE (SELECT epoch FROM control) = ?` 相当の条件を含め（`control` テーブル 1 行に epoch を複製、ControlDO が更新）、旧 epoch の request の commit を D1 側でも拒否。UploadDO/LockDO は起動時に epoch を照合し、不一致なら自身の状態を `stale` にして全操作を 409 で拒否。
6. **トークン仕様 (T1〜T6)**: 全トークンを表にする: 種別 / `typ` / 構造（HMAC-SHA256 署名付き JSON か DB 参照の不透明 ID）/ エントロピー（≥ 128 bit）/ 保存 / 期限 / 失効方法 / Cookie 属性。unlock Cookie: `__Host-ncf_share_<shareIdShort>`、`Secure; HttpOnly; SameSite=Lax; Path=/`（`/s/<id>` と `/api/v1/public/shares/<token>` の双方で使うため Path は `/`、ただし Cookie 値に share_id を含め他 share では無効）、Max-Age = min(共有期限, 7 日)、`share_version` と `kid` を含める。公開 JSON mutation（unlock、upload-only の upload 開始/complete）: `Origin` 検証（許可 origin = アプリ host のみ、`Origin: null` は拒否）+ `Sec-Fetch-Site` 検査 + JSON Content-Type 必須。KDF: 共有パスワードは PBKDF2-HMAC-SHA256 600,000 回（OWASP 2023 推奨）または scrypt (N=2^15, r=8, p=1) を採用し実測で決定、認証費用上限は per-share 10 回/分 + per-IP 30 回/分 + 全体 DO カウンタ 600 回/分。鍵ローテーション: `SIGNING_KEYS` を `kid` 付き JSON 配列 secret として保持、通常ローテは新 kid 追加 → 24h 後に旧 kid を verify-only → 7 日後削除、緊急ローテは epoch +1 で全トークン無効化。
7. **コンテンツ配信 matrix (C1, C2)**: 表を確定: 種別（image/video/audio/pdf/text/markdown/html/svg/office/その他/アーカイブページ/EPUB リソース）× 構成（CONTENT_HOST あり / 単一 host）× 応答（`Content-Type`、`Content-Disposition inline|attachment`、`CSP`、sandbox）。単一 host 構成では **inline 許可は image/video/audio/pdf/plain text のみ**、他は attachment。CONTENT_HOST 構成でも HTML/SVG は `sandbox` CSP（`Content-Security-Policy: sandbox; default-src 'none'; img-src 'self' data:; style-src 'unsafe-inline'`）で inline、EPUB XHTML も同様（script 禁止）。Markdown はサーバでレンダリングせず、クライアントで sanitize（許可タグ allowlist、`javascript:`/`data:` (画像以外) 禁止、外部画像はプロキシしない = 非表示）。ファイル名の出力先別エンコード: `Content-Disposition` は RFC 6266 `filename*=UTF-8''` + ASCII fallback、HTML は文脈別エスケープ（React のテキストノードのみ、`dangerouslySetInnerHTML` 禁止）、XML (PROPFIND) は XML エスケープ + 制御文字除去、CSV は先頭 `=+-@\t\r` をクォート、JSON は標準シリアライズ、ログはマスク後に JSON。
8. **bounded parser (I1, I2)**: 上限表を追加: JSON body ≤ 1 MiB / 深さ ≤ 32、名前 ≤ 255 byte (UTF-8) かつ 255 文字未満、パス深さ ≤ 64、URL ≤ 8 KB、XML body ≤ 1 MiB / 深さ ≤ 32 / 要素 ≤ 10,000 / property ≤ 100 / 値 ≤ 8 KB、`If` ヘッダ ≤ 8 KB / list ≤ 16、`Destination` は同一 origin かつ `/dav/` prefix 必須、`Depth` は `0|1|infinity` のみ、`Timeout` は `Second-N` のみで N ≤ 604800、`Range` は単一範囲のみ（複数範囲は 416 でなく全体 200 応答）、`Content-Length` 必須・上限、Header 数 ≤ 100。全パースは fast-xml-parser の `processEntities: false`、DTD 禁止。
9. **WebDAV ロック RFC 整合 (W1〜W3)**: RFC 4918 準拠に修正: locked resource への mutation は **lock token の提示（`If` ヘッダ）で許可**し、creator 照合は行わない（前ラウンドの「owner のみ」は UNLOCK/refresh にも適用しない — RFC §9.11 は UNLOCK に token 提示のみ要求。ただし **異なる principal の token 提示による UNLOCK は 403 とする拡張は RFC §6.4 で許容** されるので、UNLOCK のみ「lock creator の principal または同 space owner」に限定）。MOVE 時、source の lock は移動先へ引き継がない（RFC §7.5 / 9.9.3）ことを再確認し、v0.3 の矛盾記述を削除。collection ETag は strong (`"<node_id>-<revision>"`) にし、`If-Match` 必須は **ファイル content の PUT のみ**（collection や PROPPATCH は revision ベースの弱い一致で 412 を返さない）に緩める。
10. **secrets 運用 (S1〜S4)**: bootstrap は `OWNER_EMAILS` の identity が **iss+sub で初回ログイン時に一度だけ** owner 化（`control.bootstrap_done_at` を条件付き UPDATE で一回性保証）、以降 `OWNER_EMAILS` は無視（owner 追加はアプリ内操作）。鍵一覧と生成コマンド（`openssl rand -base64 32`）、保管（wrangler secret）、ローテ手順を §14 に。Workers Logs / Tail Workers の自動ログに URL が含まれるため: share token は URL パスではなく **`/s/<shareId>` + `#<secret>`（fragment はサーバに送られない）または POST body** で渡す方式に変更（公開ページの JS が fragment を読み取って `unlock`/`ticket` API に送る。JS 無効環境では token 付き URL を直接受ける `/s/<shareId>/t/<secret>` を **無効化**）。ログ設定: Workers Logs の `invocation_logs` で request URL の記録を認識し、機微情報を URL・ヘッダに載せない設計を原則とする。`DEV_BYPASS_ACCESS` は `wrangler.jsonc` の `env.production` / `env.staging` で定義不可、コードでは `env.ENVIRONMENT !== 'development'` で無視 + 起動時警告。
11. **受入試験**: §8「追加すべきセキュリティ受入試験」を全て §15 に追加。
12. **機能追加 (addendum)**: 全項目を統合。特に: 新テーブル（`node_media`, `library_items`, `user_reading_state`, `tags`, `node_tags`, `library_roots`, `node_audio`, `user_playback_state`）を §3 に、新 API を §5 の表に（manifest に登録、authorize の operation は `read` / `write` / `library.read` 等）、索引化・タグ抽出・ページサムネイルの job を §10 の Queue に（outbox・世代・費用冪等ルール適用）、zip bomb・Range 読み取り上限を §13 制限表に、リーダー/ギャラリー/プレイヤー UI を §9 に、メディア系の非目標（RAR/7z, OCR, DRM, 波形）を §0.2 に、実装フェーズに「Phase: Media library（Gallery → Bookshelf → Audio）」を追加。EPUB リソース配信は上記 matrix の sandbox ルールに従う。
